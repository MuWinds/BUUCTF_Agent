# GUI 手动测试清单

自动化测试（`src-tauri/tests/e2e.rs`）已经覆盖了协议解析、工具执行、事件序列。
**这份清单只测自动化测不到的东西**：渲染是否正确、流式是否掉帧、配色与布局、
滚动行为、交互手感。

数据来自同一套 fixture，所以自动化跑绿之后，界面上看到的应当与断言一致 ——
如果不一致，说明问题出在前端渲染层，范围已经被缩到很小。

---

## 准备

**1. 起假服务端**（会一直占着终端）：

```bash
pnpm fake-llm            # 监听 127.0.0.1:8787
```

**2. 起应用**：

```bash
pnpm tauri dev
```

**3. 在设置页填**：

| 字段 | 值 |
| --- | --- |
| API 地址 | `http://127.0.0.1:8787/v1` |
| API Key | 留空即可（假服务端不校验） |
| 模型 | 见下方每个场景的「模型」列 |
| 上下文窗口 | `128000` |

**4. 把工作区切到** `scripts/fake-llm/sandbox/`。

> 工具会真的改文件。`tool-edit` 场景跑完记得 `git checkout scripts/fake-llm/sandbox`
> 还原，否则下次断言会失败。

**场景怎么选**：模型名填成场景 id 就锁定该场景（确定性最好）；
也可以把模型名留成任意值，直接用关键词触发（更接近真实使用）。
`curl http://127.0.0.1:8787/scenarios` 可以列出全部场景。

## 场景

### 1. 基础渲染

| 模型 | `basic-chat` | 关键词 | 「介绍一下这个项目」 |
| --- | --- | --- | --- |

要看的：

- [ ] 加粗、无序列表正常渲染，**不是**原始 Markdown 符号
- [ ] ```` ```rust ```` 代码块有等宽字体与独立背景
- [ ] **流式期间**代码块就已经成形（不等轮次结束才突然重排）
- [ ] 轮次结束后整体没有「闪一下重排」的跳动

### 2. 思维链

| 模型 | `reasoning` | 关键词 | 「想一想」 |
| --- | --- | --- | --- |

- [ ] 思维链与正文分区显示，灰显且默认折叠
- [ ] 展开后内容完整
- [ ] 正文里**不含**思维链的句子

### 3. 长回答（掉帧）

| 模型 | `long-answer` | 关键词 | 「长文」 |
| --- | --- | --- | --- |

80 段文本以 5ms 间隔涌入，这是最容易暴露性能问题的场景。

- [ ] 文本平滑增长，无肉眼可见卡顿
- [ ] 视图自动跟随滚动到底部
- [ ] 生成期间手动向上滚，**不被强行拽回**底部
- [ ] 开着 DevTools Performance 录一段，掉帧不明显

### 4. 工具卡片

| 模型 | `tool-read` | 关键词 | 「读一下 README」 |
| --- | --- | --- | --- |

- [ ] 卡片**先**出现（灰色 pending），参数到齐后才显示 `Read(README.md)`
- [ ] 状态依次走 pending → running → 成功态
- [ ] 卡片出现在「我先读一下」这句话**之后**，不是之前
- [ ] 折叠态只有一行摘要；展开后能看到文件内容
- [ ] 卡片右侧显示耗时

### 5. 并行工具

| 模型 | `tool-parallel` | 关键词 | 「找一下 TODO」 |
| --- | --- | --- | --- |

- [ ] 两张卡片（Glob、Grep）各自独立，不是合并成一张
- [ ] 两张都能单独展开/折叠

### 6. Bash 流式输出

| 模型 | `tool-bash` | 关键词 | 「跑一下」 |
| --- | --- | --- | --- |

- [ ] 命令**执行过程中**就能看到输出逐行出现，不是结束后才整块出现
- [ ] 终端视图等宽字体，中文不乱码
- [ ] 显示退出码 0

### 7. 彩色 diff

| 模型 | `tool-edit` | 关键词 | 「改一下问候语」 |
| --- | --- | --- | --- |

- [ ] 先 Read 卡片，后 Edit 卡片
- [ ] diff 有增/删两种底色，深浅主题下都不刺眼
- [ ] **行内**变化部分有更强的高亮（`hello world` → `你好，世界`）
- [ ] 中文与英文混排时高亮位置不错位（这里专门盯 UTF-16 索引问题）
- [ ] 行号列正确，删除行无新行号、插入行无旧行号
- [ ] 显示 `+1 -1`

跑完记得还原沙箱。

### 8. 工具失败

| 模型 | `tool-failure` | 关键词 | 「读一个不存在的文件」 |
| --- | --- | --- | --- |

- [ ] 第一张卡片是失败态（红色），错误信息可读
- [ ] 失败**没有**让整条消息变成错误态
- [ ] 第二张卡片成功，对话正常收尾

### 9. 错误响应

模型分别填 `error-401` / `error-429` / `error-500`。

- [ ] 消息进入错误态，显示服务端给的原因（不只是 HTTP 状态码）
- [ ] 401 的提示里能看出是 Key 的问题
- [ ] 出错后输入框恢复可用，不会卡在「生成中」
- [ ] 能接着发下一条

### 10. 取消

| 模型 | `cancellable` | 关键词 | 「慢慢说」 |
| --- | --- | --- | --- |

每 400ms 一句，共 60 句，有充足时间点停止。

- [ ] 生成期间「停止」按钮可见可点
- [ ] 点击后**立刻**停止，不是等几秒
- [ ] 已经吐出的内容**保留**，不被清空
- [ ] 消息标记为已取消（与正常完成有视觉区分）
- [ ] 可以马上发下一条

### 11. 空流

| 模型 | `empty-stream` | 关键词 | 「空流」 |
| --- | --- | --- | --- |

- [ ] 不会永远转圈
- [ ] 显示明确提示，而不是一个空气泡

### 12. 用量显示

任选一个带 usage 的场景（如 `tool-read`）。

- [ ] 状态栏出现 token 用量与上下文占用环
- [ ] 占用比例是合理值，**不会超过 100%**（累加值当占用会算出 300% 这种数字）
- [ ] tps 是合理数字

### 13. 重试

设置页把「重试次数」留空（= 无限重试），模型填 `retry-then-success`（前两次请求返回 503，第三次成功）。

- [ ] 前两次请求失败时，消息上方出现黄色横幅：失败原因、第几次重试、等待秒数
- [ ] 无限重试时横幅标注「无限重试，可点停止退出」
- [ ] 第三次成功后横幅消失，回答正常流出，消息正常收尾
- [ ] 退避等待期间点「停止」能立刻退出，消息标记为已取消
- [ ] 把「重试次数」填 0（= 不重试）后发 `retry-exhausted`：直接进入错误态，显示服务端原因，不出现重试横幅

## 跨场景

### 会话分叉（回退）

任选一个多轮场景（如 `tool-read`）跑几轮后操作。

- [ ] 历史消息 hover 时右上角出现「分叉」按钮
- [ ] 点击后：该消息之前的内容保留，之后的消息消失
- [ ] 会话列表里出现**两个**会话：当前（截断后）+ 旧分支（完整），都能切回
- [ ] 从分叉点继续发消息，新分支正常对话
- [ ] 流式生成期间（streaming）不显示分叉按钮

### 上下文自动压缩

把设置页的「上下文窗口」调小（如 `200`），发一条长消息触发。

- [ ] 消息列表出现「上下文已自动压缩」气泡，可看到摘要内容
- [ ] 最老的消息被摘要替换，最近的消息保留
- [ ] 压缩后继续对话正常，模型能读到摘要中的关键信息
- [ ] 重启应用后，摘要气泡仍在（Summary 条目随会话落盘）

### 会话持久化

- [ ] 跑完 `tool-edit` 后重启应用，diff 卡片**原样还原**（不退化成纯文本）
- [ ] 终端输出、工具耗时都还在
- [ ] 思维链折叠状态正常

### 主题

- [ ] 深浅色主题切换后，diff 底色、工具卡片状态色、思维链灰度都仍然可读
- [ ] 没有硬编码成固定色而不跟随主题的地方

### 切换工作区

- [ ] 切换后会话被清空
- [ ] 新工作区下工具能正常读到文件

## 发现问题后

先判断层次：

1. `cargo test --test e2e` 也失败 → 问题在 Rust 侧，照着失败的断言查
2. 只有界面不对 → 问题在前端渲染层，看 `src/components/`
3. 两边都对但观感差 → 性能问题，录 Performance 看掉帧

能用测试守住的，补进 `src-tauri/tests/e2e.rs` 或 `src/**/*.test.ts`，
别让同一个问题需要人工发现第二次。
